# 答辩与演示提纲

## 建议演示顺序

1. 启动界面，运行经典反例，指出贪心160与最优220的区别。
2. 选择动态规划结果，查看B、C被选中，容量使用率100%。
3. 将容量改为40，说明旧结果被清空；重新运行并解释新的选择。
4. 生成24件物品，设置限时0.5秒，展示超时状态不等于已证明最优。
5. 打开 `results/reference/n_runtime.svg` 与容量曲线，结合原始数据说明趋势。
6. 执行 `python -m unittest discover -s tests -v`，说明随机交叉验证方法。

## 常见问题

**为什么叫0/1背包？** 每件物品只能选或不选，不能切分，也不能重复拿。

**为什么价值重量比贪心不保证最优？** 局部占用容量可能阻挡更好的组合。
经典例子选择A+B价值160，但B+C价值220。

**动态规划为什么倒序遍历容量？** 要让本轮读取的前驱状态仍然属于上一轮物品集合。
正序会重复使用当前物品，变成完全背包。

**动态规划的空间真是O(C)吗？** 本项目的价值数组是O(C)，但为了回溯所选物品，
还保存n行bytearray决策，总空间是O(nC)。报告已明确这一点。

**分支限界为什么可以剪枝？** 将剩余0/1物品放宽为可切分物品得到价值上界。
若上界都不能超过已知可行解，该分支不可能改善结果，可以舍弃。
整数价值允许把分数上界向下取整；代码全程用整数计算这一上界。

**上界和下界分别是什么？** 上界来自放宽后的分数背包，下界是已找到的真实可行解价值。
初始化下界用贪心算法；搜索会继续改进它。

**分支限界为什么在实验里很快？** 独立均匀随机实例的分数上界较有效。
不能推导出它在强相关、同密度或更大实例上始终很快；最坏仍可能指数增长。

**为什么动态规划是伪多项式？** 时间依赖容量的数值C，容量用二进制输入只需约log C位。
因此O(nC)不是对输入编码长度的普通多项式。

**超时返回的结果是什么？** 当前已知可行解，可能恰好等于最优值，但搜索尚未完成，
因此仍标记timeout，不能宣称已证明最优。

**如何证明程序没超重、没重复拿物品？** 独立校验器重新统计编号、重量和价值；
小实例另用独立枚举程序核对最优值，避免只拿两个相似实现互相验证。

**为什么不选遗传算法？** 本题可以用动态规划和分支限界获得精确基准，
先把精确性、对比实验和可解释性做扎实；遗传算法不是原题强制要求。

**数据怎么来的？** 固定种子生成的整数随机实例，不是真实物流数据。
全部输入保存在instances.json，计时结果保存在raw.csv。
